# 输入设计与预演门禁

在正式写视频 Prompt 前，先判断模型能否从输入直接读懂身份、空间和关键物理状态。复杂镜头优先修正输入，不用更长的文字掩盖错误或缺失的视觉信息。

## Input Design Gate

依次检查：

1. **身份**：当前人物、服装、道具和载具是否已有生产级参考。
2. **空间**：不看文字时，是否能判断谁在谁的上方、前后、左右和运动方向。
3. **初始状态**：第 0 帧必须成立的倒置、悬空、抓握、接触、破损、受力或遮挡是否可见。
4. **动作路径**：起点、关键锚点、运动方向和终点是否可预演。
5. **参考构图政策**：每张图是片段内部的视觉锚点（分镜图默认）、首帧/尾帧（只限接帧、延长、精确复现），还是只提供身份、布局、状态或观感。

任一关键项不可读时，先补 Layout Plate、Shot State Plate、关键帧或白模。全部可读后标记 `INPUT_READY`，再进入 Scene Map、Shot Card 和 Prompt Writer。

`NOT READY` 时先交付缺失输入资产的制作方案或生图 Prompt，不把高风险镜头伪装成已经可以正式生成。只有用户明确要求带风险继续时，才同时提供视频 Prompt，并标明预期失败点。

## 四类输入资产

- **Canonical Asset**：长期复用的身份、结构和固定外观。
- **Continuity State Asset**：跨多个镜头持续的湿、脏、伤、换装、昼夜或破损状态。
- **Layout Plate**：只预演人物、物件、场景锚点、起点、终点和运动方向；默认不控制最终画风和构图。
- **Shot State Plate**：只服务当前镜头的困难初始物理状态，例如倒置充血、悬空抓握、钢缆已绷紧或身体已处于碰撞前一刻；不升级为 Canonical Asset。

长期连续状态使用 Continuity State Asset。只在单镜头第 0 帧必须成立、且模型难从文字可靠推断的状态使用 Shot State Plate。

## Reference Role

每份视觉输入只指定一个主要角色：

| Role | 控制内容 | 构图政策 |
|---|---|---|
| `VISUAL_ANCHOR` | 片段内部某个时间窗口的主体关系、构图、景别、机位方向和关键道具状态 | 在声明的时间窗口用运镜抵达，前有引入段、后有过程或出口段；**不是首帧，也不是尾帧**，不定格。分镜图默认用它，见 [关键帧分镜白模](keyframes-storyboards-white-model.md) |
| `START_FRAME` | 开始构图、位置、姿态、道具和镜头方向 | 精确继承首帧，并锁定本镜头开场构图；只用于接帧、向后延长、精确复现 |
| `END_FRAME` | 最终构图、位置、姿态、道具和镜头方向 | 明确到达尾帧；只用于向前延长、静止落版 |
| `IDENTITY_ONLY` | 五官、发型、服装、结构或物件身份 | 不继承背景、姿势和 framing |
| `LAYOUT_ONLY` | 空间关系、动作起点、锚点和运动方向 | `REFERENCE ONLY, NOT A START FRAME` |
| `STATE_ONLY` | 倒置、悬空、抓握、受力、破损等状态 | 只继承状态，不默认复制构图 |
| `CAMERA_PREVIS` | 视频中的摄影机路径、朝向、取景变化和时序；动作/灯光另行声明 | 继承声明的动态构图，见 [摄影预演](../director/blender-camera-previs.md) |
| `LOOK_ONLY` | 材质、光线、色温、雾气和调色 | 不控制人物、动作和 framing |

## Reference Role 优先级

先检查显式主源。指定 `CAMERA_PREVIS` 时，它拥有声明的摄影维度；首尾图与它冲突应先修复输入，不按图片优先直接覆盖轨迹。以下为未指定摄影预演主源时的默认优先级：

1. `START_FRAME`：控制开场构图、人物占屏、裁切、开场姿态和镜头方向。
2. `END_FRAME`：控制结束构图、人物占屏、裁切、结束姿态和镜头方向。
   `VISUAL_ANCHOR`：控制它所在时间窗口的构图和主体关系，与首尾帧同级，只是时间位置在片段内部；各锚点时间窗口不重叠。
3. `SCENE GEOGRAPHY LOCK`：控制世界空间、固定锚点、屏幕左右、摄影机侧和轴线。
4. `LAYOUT_ONLY` / TIG blocking map：控制当前镜头的人物位置、朝向、姿势和运动起点，不夺取首尾帧构图。
5. 参考视频：默认控制动作节奏或摄影机路径，除非另有声明。
6. 文字：补充图片和视频无法稳定表达的动作因果、台词、声音和终态。

同一维度只能保留一个主控制源；无法判定主源时先标记 `INPUT GATE：NOT READY`。

## 构图锁定决策

布局/状态参考默认**不锁定构图**；显式 `CAMERA_PREVIS` 按其声明继承动态构图。先判断参考图在当前镜头中的职责：

- 有分镜图、要让画面“经过”某个构图时，默认使用 `VISUAL_ANCHOR`：写清时间窗口、抵达方式和离开理由，锚点前后都在运动。（用户实测：比首尾帧稳定得多。）
- 需要首帧精确复刻、连续镜头接帧、产品展示构图或严格复现 approved 画面时，才使用 `START_FRAME`，锁定开场构图、人物占屏、裁切和镜头方向。
- 只需要多人空间关系、站位、朝向、动作起点或运动方向时，使用 `LAYOUT_ONLY`，只锁定空间几何，不锁定机位、景别、占屏和最终风格。
- 需要特殊物理初始状态时，使用 `STATE_ONLY`；除非另有声明，不继承原图构图。

因此，TIG blocking map 默认作为 `LAYOUT_ONLY` 使用；只有用户明确要求按参考图复刻构图，或该图承担 `START_FRAME` 职责时，才升级为构图锁定。换机位、正反打或景别变化时，不沿用上一颗镜头的构图锁定。

一张图确实需要承担多个维度时，逐项声明，但仍指定一个主 Role；若职责互相冲突，拆成独立图片。

## 素材声明模板

```text
@图片N 或 @视频N（CAMERA_PREVIS 用视频）
ROLE：[VISUAL_ANCHOR（锚点N｜时间窗口） / START_FRAME / END_FRAME / IDENTITY_ONLY / LAYOUT_ONLY / STATE_ONLY / LOOK_ONLY / CAMERA_PREVIS]
ADOPT：[只采用的属性]
IGNORE：[不得继承的背景、人物、姿势、文字或临时物件]
FRAMING POLICY：[片段内部抵达，不是首尾帧 / 精确继承 / 只参考 / 明确不是首帧]
```

对于非首帧布局图，明确写：

```text
@图片N是 LAYOUT_ONLY，只用于空间关系、动作起点和运动方向。
REFERENCE ONLY, NOT A START FRAME. 不复制其开场构图、机位或占屏。
```

## 烘焙决策

- **不要烘焙**：对白、完整动作过程、临时摄影机运动、声音、无关背景细节和可由视频自然完成的普通姿态变化。
- **可以烘焙**：第 0 帧必须成立、直接决定重力或接触关系、且连续测试证明文字难以稳定建立的关键状态。
- **烘焙后仍需写动作**：输入只负责起始状态，视频 Prompt 继续负责触发、过程、物理反馈和终态。
