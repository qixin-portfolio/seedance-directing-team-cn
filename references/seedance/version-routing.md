# 版本路由

纯摄影设计、Blender 交接或预演审查不依赖 Seedance 平台能力，可以先完成；进入生成转译、上传或平台参数设置时再确认版本和 Surface。

## 判断顺序

1. 用户明确写出 `Seedance 2.0` 或 `Seedance 2.5`：严格使用该版本。
2. 用户明确提到当前界面功能：先判断版本，再加载 [平台路由](surface-routing.md)；不要把一个平台名称外推为所有平台能力。
3. 用户没有说明版本：简单任务可按 Seedance 2.5 组织并标注“版本待确认”；正式生产镜头、编辑、延长或依赖具体能力的任务，先确认版本和 Surface。
4. 用户给出旧版提示词并要求升级：保留创意、Canonical Descriptor、已确认资产和 Scene Map，按 2.5 工作流重组，不照抄旧限制。

## Seedance 2.0

- 简单多模态任务使用路径 A；复杂影视化任务使用路径 B 三段论。
- 复杂分镜优先使用镜头顺序，不依赖精确绝对秒数。
- 单镜头只设置一个主要运镜。
- 使用 `@图片N / @视频N / @音频N` 和有语义主体桥接素材。

## Seedance 2.5

- 普通叙事优先阶段；关键交接可用时间区间、时间点或相对时间。
- 支持首尾帧、多关键帧、宫格分镜、视频编辑、向前/向后延长、白模、一键成片和无缝转场等官方指南工作流；是否在当前平台暴露以 Surface 为准。
- 编辑与延长遵守输入素材自动锁定的画幅或时长规则。

## 冲突处理

- **不得把 2.0 的限制当作 2.5 能力边界**。
- 不得把 2.5 的功能默认写给 2.0。
- 素材职责唯一、可观察终态、Canonical Descriptor、Scene Map、Auditor / Workbench 等跨版本制作方法可以复用，但其中后几项属于项目生产经验，不是官方版本能力。
- 用户资料与公开资料冲突时，优先采用用户指定的当前版本和 Surface；能力边界保持条件表述。
