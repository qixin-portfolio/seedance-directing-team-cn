# 影视资产生产系统

影视资产不是一张漂亮图片，而是一对可复用对象：

`资产 = Canonical Descriptor（固定文字描述符） + Reference Image（参考图）`

## Canonical Descriptor

关键人物、场景和道具都应有一段锁定描述。资产通过后，这段文字在后续镜头中**逐字复用**，不要不断用同义词改写身份特征。

人物建议拆成：

```text
BASE IDENTITY：
年龄范围、脸部结构、发型、体型、肤质、固定服装结构、固定配饰、默认姿态与气质。

STATE OVERRIDE：
仅写本状态新增或改变的内容：湿、脏、伤、换装、疲惫、血迹、破损等。
```

## 人物设定板

人物资产图默认用 [人物资产设定板模板](character-sheet-template.md)：16:9 五格（无头正面、无头 90 度左侧、背面、正脸、45 度左脸），写实棚拍皮肤与布光段逐字复用；不能站立的人物用模板里的姿态变体。

## 状态资产

同一角色、场景或道具发生明确状态变化时，新建**状态资产**，不覆盖旧版本。

示例：

- `@char_BX_deliveryman_clean_v01`
- `@char_BX_deliveryman_rainwet_v01`
- `@char_BX_deliveryman_injured_v02`
- `@loc_BX_riverside_day_v01`
- `@loc_BX_riverside_rain_v01`

状态变化只改 STATE OVERRIDE；BASE IDENTITY 保持不动。

## 连续状态与单镜状态

跨多个镜头持续的湿、脏、伤、换装、昼夜或破损使用状态资产。只在当前镜头第 0 帧必须成立、且模型难从文字稳定推断的倒置、悬空、抓握、接触或受力状态，建立非 Canonical 的 `Shot State Plate`。不要把 Shot State Plate 反向升级成角色默认身份。具体门禁见 [输入设计与预演](input-design-and-previs.md)。

## 审批层级

- `VISUAL_APPROVED`：静态资产在身份、结构、材质、构图上通过。
- `PRODUCTION_APPROVED`：经过视频压力测试，确认在计划使用的景别、动作、场景和多人关系中仍可用。

没有经过压力测试的关键人物，不自动视为生产级资产。

## 图片资产与视频 Prompt 分轨

影视资产图优先：中性、易读取、光线不过度风格化、背景不抢主体、道具可拆分。视频 Prompt 才负责 blocking、FOV、动作、物理、戏剧性光线和声音。两类规则不要混写。

## 资产里的文字

场景和道具在现实中本来就有的文字——招牌、门牌、标签、包装、证件、屏幕、告示——**直接生成进资产图**，不留空白招牌、不留无字标签。先写文字清单（内容逐字、字体、工艺材质、位置、分级），A 级叙事文字写进 Canonical Descriptor 并逐字锁定。规则见 [画内文字系统](in-world-text.md)。

“禁止烘焙进资产的临时信息”指的是只属于某一镜头的状态（溅上的水、临时贴纸、一次性屏幕内容），不是指场景固有文字。

## 项目经验，不是官方硬规则

三联人物卡、无头全身图、笑/不笑两套近景、三分之四场景 Plate 等可作为高价值实验策略；它们来自生产项目经验，不是 Seedance 官方要求。先做小样测试，再决定是否成为本项目资产规范。
