# 知识分级、经验沉淀与项目风格档案

## 1. 两套标签，一起用

**来源层级**（这条知识从哪来）：

- **官方**：Seedance 官方指南/文档写明的能力和语法；
- **平台**：即梦、Higgsfield、API 等当前界面或文档实际暴露的参数与入口；
- **项目经验**：外部或本团队生产中验证过、但非官方的方法（如 15-Block、Workbench、三联人物卡）；
- **本项目约定**：当前项目自己的决定。

**稳定性**（这条知识能用多久）：

- **P｜跨项目原则**：多次独立案例验证，跨模型仍成立；
- **O｜当前操作参数**：模型版本、时长、分辨率、提示词长度、成本、成功率、重试数——必须注明 `valid_as_of`；
- **C｜项目设定**：特定角色、场景、视点、美术、连续性或用户口味。

不让项目经验冒充官方规则，不让 O 冒充 P，不让 C 污染通用 Skill。

## 3. 已有导演知识卡（来自 Leos 六部门导演组，作为起点）

1. **K01 先定场，后群戏**：共享空间关系是多人覆盖的前提。
2. **K02 参考资产单一职责**：构图、角色、场景和气氛分开承担控制。
3. **K03 重要信息需要反应时间**：揭示后为角色和观众保留消化过程。
4. **K04 生成失败先改条件**：第二次重试必须包含根因诊断。
5. **K05 整条不重跑，只补缺口**：先在时间线识别真正缺镜。
6. **K06 场景必须有自主生活**：背景活动不只等待主人公。
7. **K07 抽象文字先视觉化**：心理和状态改写成可见行为。
8. **K08 权力感依靠气口**：停顿、注意力和动作节制比表情标签更有效。
9. **K09 关键场景先审批气质与结构**：空间身份错误会污染后续全部镜头。
10. **K10 先形成粗剪，再判断缺镜**：时间线比孤立素材更能暴露问题。
11. **K11 小范围试生成阻断方向错误**：扩展镜头组前验证空间、表演和资产。
12. **K12 完成度优先于低价值精修**：先让整段成立，再修次要瑕疵。
13. **K13 好表演优先保护**：用剪辑和局部补镜处理小连续性。
14. **K14 画外空间也是导演工具**：用遮挡、声音、局部和反应保留叙事功能。
15. **K15 先校验空间可行性**：剧本调度与权威场景冲突时先重设调度。
16. **K16 提示词助手必须共享上下文**：先给场景、角色、轴线和导演意图。
17. **K17 段落之间保留重叠覆盖**：主动设计可剪接缝。
18. **K18 第二次生成必须有人类复盘**：AI 负责结构化，人负责导演判断。
19. **K19 大全景先签尺度契约**：用门高、人车比和建筑层高验收比例。
20. **K20 可辨认角色都有镜内任务**：按可辨认程度分配精度，反应要有真实触发；远景按区域组织，允许有因同步（v1.3 据 Seedance V2.3 镜内生态修正）。
21. **K21 人物光必须响应环境**：光区变化时同步改变脸部亮度、色温与方向。
22. **K22 道具与动作使用状态机**：记录初始、变化和结果状态。
23. **K23 危险感需要地理证据**：用桥外、断面或参照物证明临界距离。
24. **K24 台词必须拥有视觉前因**：评价变化前先让观众看见变化。
25. **K25 互动分支分别设计调度**：不同选择拥有不同动作顺序与表演状态。
26. **K26 场面能量需要动作桥**：用声音、环境动作和自然入场连接情绪动能。

候选启发（heuristic，需本项目积累独立样本后再升级）：H27 可演动作优先于情绪标签；H28 刺激先于反应；H29 微表演限制通道；H30 单变量重试；H31 入口/出口状态接镜；H32 先定案再编译提示词；H33 摄影参数必须有可见目的；H34 提示词版本与 Take 分账；H35 项目风格独立沉淀。

原始 Skill 的会议来源（M01–M13）为作者内部资料、无法核验，本版不再引用；新增知识卡请用本项目的 Take ID 与提示词版本作证据。

## 4. 证据门槛

- 一次成功/失败：只记观察，不写永久规则。
- 同一镜头的多次随机结果：可形成模型倾向，仍属 O。
- 至少两个独立镜头/场次出现同样因果，或导演明确定为创作规范：可形成候选 P/C。
- 跨模型仍成立、无关键反例、步骤可复现：才升级为高置信 P。
- 模型版本、参数、价格、时长、提示词长度和成功率始终为 O，注明 `valid_as_of`。

反思链条：`原始提示词 + 参考 + 参数 + 输出 → 症状/成功点 → 根因假设 → 单变量修改 → 新结果对比 → 候选经验 → 证据复核 → 知识卡 → 更新 Skill`。保留反例，不只收集成功样本。

## 5. 项目风格档案

用户对项目的口味、摄影规则或提示词偏好默认写入 `assets/project-style-profile-template.json`，类型 C。一次反馈记 `candidate`；用户明确确认或本项目多例成立后记 `confirmed`；模型专属经验归 `model_specific_rules`（O）。不把项目偏好直接写进通用 Skill。

## 6. Skill 更新门槛

只在用户提供一批新审片/生成记录或明确要求更新时运行：

1. 在实验账筛选 `知识卡候选=是` 的记录并核对原始素材；
2. 合并重复结论，寻找反例和适用边界；
3. 判断应更新导演层、执行层、审片路由还是项目配置；
4. 先写知识卡，再修改对应参考文件；
5. 不把项目角色或场景设定写成跨项目原则；
6. 新证据推翻旧结论时标记“已修正/已降级”，不静默覆盖历史；
7. 不让提示词导演自行改写 Skill，更新需用户同意。
