## 1. 连续性矩阵

每个镜头检查：

| 维度 | 检查内容 |
|---|---|
| 人物身份 | Canonical Descriptor、五官、年龄、发型、体型、数量 |
| 状态资产 | clean / wet / injured / day / night 等版本是否正确，不把旧状态覆盖掉 |
| 服装妆造 | 款式、颜色、材质、扣子/拉链/袖口、脏污、血污、伤势位置与阶段 |
| 场景结构 | 门窗、家具、建筑、光源、固定背景与 World Bible |
| 画内文字 | 招牌、门牌、标签、屏幕等文字内容、字体、位置与亮灭状态是否与资产一致 |
| 场景地理 | `SCENE GEOGRAPHY LOCK`、空间锚点、世界方向、屏幕方向 |
| 人物方向 | 身体朝向、视线落点、进入与离场方向 |
| 轴线 | 摄影机是否越过 180° 线；越轴是否有意设计 |
| 动作 | 上镜结束状态是否成为下一镜开始状态；动作相位 |
| 手与道具 | 左右手占用、数量、归属、开合、完整/损坏、干湿、点燃、喝过/吃过 |
| 摄影机 | 机位、景别、焦距/FOV、运动趋势、焦点和高度 |
| 演技 | 角色表演档案是否保留；注意对象、呼吸、强度；情绪尾巴是否接到下一镜 |
| 环境 | 门窗、车辆、灯具、烟火、背景人物、时间、天气和光区 |
| 声音 | VOICE PROFILE、台词版本与归属、环境声、音乐、动作音效 |
| 物理因果 | 力量来源、接触点、传力路径、承受对象反作用和 endpoint 是否连续 |
| 输入职责 | Reference Role、首帧政策、Layout / Shot State Plate 是否正确使用 |
| 可剪性 | 稳定可用区间、叙事功能、进入和离开镜头的衔接点 |

## 2. 入口—变化—出口

每个镜头至少记录 `入口状态 → 变化事件 → 出口状态`。首帧应处于“动作将起或刚起”，不为建立空间浪费空首帧。用视觉锚点的片段，出口状态写在【结束状态】里（主体仍在运动、接口元素），下一片段的引入段从这里继续；需要逐帧接上时，才用上一片段实际采用素材的最后一帧当 `START_FRAME`。上一镜已经湿、脏、破损、打开或持有的状态，下一镜继续保持，除非剧情明确改变。

镜头设计至少写：上一镜连续性、下一镜衔接、空间锚点、绝对禁止项、首帧生图提示词（需要时）、图生视频提示词、验收标准。

### 关键状态的累积变化

对影响剧情或跨镜可读性的消耗、损伤与累积变化，记录 `进入状态 → 本镜变化 → 离开状态`。如“完整饼干 → 咬掉一口 → 带缺口的饼干”；下一镜从**实际采用素材**的离开状态开始，不能无故恢复完整。

只有在剧情明确清理、修复、补充、更换或跳时后恢复时才重置，并给出依据。仅追踪关键人物和道具，不给所有背景物件建立台账。计划状态与生成结果不同时，先判断是否破坏剧情；不默默沿用失败结果，也不凭计划声称状态已实现。

## 3. 连续性等级与接镜检查

- **硬连续性**：身份、空间方向、关键道具、动作因果、伤势阶段、台词事实。冲突破坏理解，列 P0；场记可据此阻止进入批量生成。
- **表演连续性**：目标、注意力、呼吸、动作相位和强度。通常 P0/P1。
- **软连续性**：衣褶、细小背景、轻微手位。核心表演成立时优先剪辑、遮挡、编辑或补镜。
- **有意断裂**：越轴、跳切、时间跳跃等导演选择。必须写清意图和建立方式，不能事后把错误称为风格。

接镜比较**上一镜最后可用帧与本镜第一可用帧**，不比较整条素材的默认首尾。差异表写：字段、上一状态、本镜状态、严重级、是否有意、首选修法和验收条件。

## 4. APPROVED 锁定

只有用户明确说“锁定这个版本”“标记为 APPROVED”或“后续沿用这一版”时才正式锁定。**“通过”“可以了”默认只表示候选接受，不自动冻结版本**；已有明确锁定授权则直接沿用。正式锁定后：

1. 当前版本成为 `<镜头编号>_APPROVED`，是正式基准；
2. 后续不得擅自改变已确认的人物、状态、服装、场景地理、方向、轴线、道具、摄影和声音；
3. 局部返修进入 [Workbench](prompt-workbench.md)，明确 PATCH 区块和保持不变区块；
4. 不因新随机结果更“漂亮”而牺牲生产连续性。

### 候选与 Selects

生成结果进入剪辑前，按 [生成实验与 Selects](generation-experiments-and-selects.md) 记录候选任务 ID、模型与 Prompt 版本、可用区间、叙事功能、上下镜衔接和区间外失败。系统可以推荐 Select，只有用户确认后标记 `SELECT_APPROVED`。`SELECT_APPROVED` 只锁定某个源素材的可用时间段；整条镜头或剪辑组合仍需用户确认 `<镜头编号>_APPROVED`。

资产编号保留项目现有体系，可在末尾加状态与版本，例如 `@char_BX_name_rainwet_v02`。编号是项目管理标识，不替代 Canonical Descriptor，也不替代提示词中的 `@图片N`。

## 5. 三本账

连续项目由场记维护三类互相关联但不混用的记录（轻量档可跳过）：

| 账本 | 证明什么 | 模板 |
|---|---|---|
| 连续性账 | 相邻镜头与场次在故事世界里能接上 | `assets/continuity-ledger-template.csv` |
| 提示词版本账 | 每版提示词来自哪些定案、吸收了哪些意见、相对上一版改了什么 | `assets/prompt-version-log-template.csv` |
| Take/实验账 | 某版提示词产生了什么结果、下一次为何这样改 | `assets/take-prompt-log-template.csv` |

用项目、场次、镜头号、提示词版本和 Take ID 关联。需要文件时直接复制模板，不临时发明另一套字段。

简版 Workbench 日志可直接写在对话中：

```text
03-03_T01 — 初版 — FAIL：身份稳定，车头错误
03-03_T02 — PATCH LOCATION MAP — FAIL：方向正确，动作过快
03-03_T03 — PATCH ACTION TIMING — PASS
03-03_APPROVED — 正式基准
```

## 6. Take 结论

每个 Take 一个且仅一个主结论：

Take 结论与 Selects 状态的对应：过/保 → 推荐为 Select 候选（用户确认后 `SELECT_APPROVED`）；修 → `CANDIDATE`，进 PATCH 或实验；废 → `REJECTED`。

- **过**：作为该镜头主版本进入时间线；记录首选可用区间。
- **保**：不是完整主版本，但有稀缺表演、动作、环境或接缝区间必须保存。
- **修**：核心设计成立，存在可定位问题；写明保留区间和最小修法（编辑 / PATCH / 补镜）。
- **废**：无可用区间或 P0 根因贯穿整条；仍记录失败类型，避免重复生成。

导演组档附角色短评：总导演看叙事/节奏，表演指导看行动真实，镜内执行导演看镜内生态，摄影指导看摄影语言，场记看连续性。总导演作最终结论，场记原样记录。

## 7. 提示词实验协议

每版最终提示词先记录：授权依据（导演组档）、完整提示词或文件、有效字符数、版本号、上游设计版本、项目风格版本、相对上一版变化、审稿结论和批准状态。

实际生成后再记录：Seedance 版本、平台、参数、参考资产、输出文件、可用时间段、成功点、症状、根因判断、下一版只改的一项、验收条件和结果对比。

单变量迭代：一次只改变一个因果变量（主体动作、时间关系、镜头运动、环境动作、参考资产、模式或模型之一）；允许同步修改该变量的必要依赖项，记为同一个“修改包”。互不依赖的多项同时修改时标记 `组合改动，无法单独归因`，不得据此宣称某一词必然有效。有两个可验证方案时用 [控制变量实验](generation-experiments-and-selects.md)。

失败分类统一使用 [审片与返修](review-and-repair.md) 的问题来源表。症状与根因分开：“人物僵硬”是症状，“没有真实任务”才可能是根因。
